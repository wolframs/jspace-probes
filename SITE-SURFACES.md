# Site surfaces — staleness inventory

For future sessions closing an expedition. Catalog only — see git log for
whether anything below has actually gone stale since this was written
(2026-08-17). NOTE: every row marked **STALE NOW** below was fixed the
same day in the commit that added this file (counts 137/499/285/94/49
corrected, unit15Overview qualified); the markers are kept as specimens
of where drift happens. Not a substitute for the record-coverage audit or the
binding-doc (MECHANICS/PREDICTIONS/GLOSSARY) staleness audit — this is the
list of WHERE facts live, especially the ones a re-run doesn't touch.

## Expedition-close checklist (5 lines)

1. Run `.venv/bin/python probes/lab.py` (reindex) then `probes/site.py` then
   `probes/og.py` — regenerates r/, og/, sitemap.xml, llms.txt, essay.html,
   glossary.html, and patches dashboard/index.html's SEO+static-index blocks.
2. Grep dashboard/app.js for the record count baked into ENTRANCE/EXTENDED
   tour prose (`grep -n '499\|285\|94 records' dashboard/app.js`) — site.py
   does NOT patch tour text; these are hand strings, drift silently.
3. Diff dashboard/app.js's `UNIT_NAMES` against probes/site.py's
   `UNIT_NAMES` (site.py comment: "mirrors dashboard/app.js — keep in
   sync") — no script enforces this, only human memory.
4. Check `dashboard/findings.json` themes/items still cite counts that
   match current results (it feeds llms.txt via site.py AND is fetched
   live by the dashboard findings modal — one hand-authored source, two
   surfaces).
5. Grep root docs for stale record counts: `grep -rnE "[0-9]{2,4} (records|experiments|scripts)" README.md AGENTS.md CLAUDE.md PLAIN-LANGUAGE.md probes/ste.py` — none of these are patched by any script.

## SEMI — patched in place but ONLY when the script is run; drifts silently between runs

Same rows as AUTO above but flagged again for the specific risk: **site.py
patches dashboard/index.html in place — if a session edits index.html by
hand between runs (e.g. adding a nav link) and then forgets to re-run
site.py, nothing enforces consistency.** The patch is surgical (regex
between comment markers) so hand edits OUTSIDE the markers survive a
re-run — but anything hand-added INSIDE `seo:begin/end` or
`static-index:begin/end` gets silently clobbered next run.

What's OUTSIDE the patch markers in `dashboard/index.html` (site.py never
touches these — pure HAND territory):
- `<title>J-Space Probes</title>`
- masthead: `<h1>J‑Space Probes</h1>`, subtitle "Reading silent thoughts
  through the Jacobian lens · wolfram × claude · RTX 3090"
- nav links (`#findings`, `#explore`, `#essay`, `../glossary.html`,
  `#board`, `#affect`, GitHub link, zip-archive link)
- favicon (`data:image/svg+xml` inline, color `#4a3aa7`) — NOTE this does
  not match `probes/site.py`'s `ICON` constant (`#3987e5`) used on all `r/`
  pages, essay.html, glossary.html; a design drift, not a fact drift, but
  the two icons visibly disagree
- console panel copy (theme/atmosphere/tours labels)
- `?skin=` allowlist (`paper`, `instrument`, `core`) — goes stale if a skin
  file is added/removed under `dashboard/skins/` without updating this list
